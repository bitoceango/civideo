# 需求文档：App 看 / 听分 Tab + 全局音频播放器

> 编号：004 ｜ 状态：草稿（待评审）
> 创建日期：2026-06-13 ｜ 关联：003（电子书→播客，提供 CLI/Worker/数据模型/基础播放）、001（三大模块重构，提供 首页/分类/我的 视频侧 Tab）、设计稿 `designs/tabs-video-listen/index.html`

## 1. 背景与目标
003 已让「听书」能产出并基础可播,但听书是塞在视频库页里的一行,看和听混在一起、体验割裂,且音频播放是**页面级**的(离开播放页就停,不能边听边逛、不能后台续播)。

本需求把 App 重构为 **「看」「听」在底部 Tab 上分开 + 一个全局音频播放器**:视频和听书各有独立 Tab、各自浏览;听书有**常驻迷你播放条**(跨 Tab、后台续播)、**全屏播放器**与**睡眠定时**。让两种内容在同一个 App 里自然共存。

**核心目标**:孩子在一个 App 里,「看视频」和「听书」是两个清爽独立的入口,但听书能像真正的播客一样**边听边逛、熄屏续播、睡前定时**。

## 2. 范围
- **本次要做（In scope）**：
  - 底部 Tab 壳 `RootTabView`:`首页 ·（分类）· 听书 · 我的`（「分类」由 001 提供,本次只新增「听书」Tab,并与 001 合流）。
  - **听书 Tab**:独立书架页 —— 继续收听 + 分类筛选(国学/故事/科普…) + 书籍网格;复用 003 的 `AudiobookDetailView`(章节列表)。
  - **全局音频播放器** `AudioController`（`AppModel` 持有,跨页面/跨 Tab 不中断）。
  - **迷你播放条**:听书在播时常驻底部(Tab 之上),点开 = 全屏播放器。
  - **全屏听书播放器**:由 003 的页面级 `AudioPlayerView` **重构为全局视图**;章节切换 / ±15s / 进度 / 收藏。
  - **睡眠定时器**(睡前听 N 分钟自动停)。
  - **后台/熄屏续播**(已具备 `UIBackgroundModes: audio`,本次确保全局播放器配合)。
- **本次不做（Out of scope）**：
  - 视频侧 001 的首页/分类/我的具体内容(各自需求);PDF 输入;本地 TTS 兜底;字幕逐句跟读;锁屏防误触(音频场景优先级低)。

## 3. 设计原则 / 约束
- **封闭花园 / 儿童友好 / 家庭量级**：同 001/003。
- **看听对等但分离**：各自独立 Tab,互不干扰;但共用账号、共用家长管控(时长/时段对视频和听书统一生效)。
- **不新增后端**：复用 003 的 manifest(`audiobooks`)、Worker(`/api/library` + `/media/audiobooks/...`)。本次纯 App 层。
- **与 001 合流**：底部 Tab 壳对齐 001 的 `RootTabView`,在其上加「听书」Tab;若 001 未合并,本次先建最小壳(首页=现有视频库、我的=家长中心),「分类」留给 001 接入。

## 4. Epics 与 Stories

### Epic F：底部 Tab 壳 + 听书 Tab
**目标**：看/听在 Tab 上分开;听书成为一等 Tab(独立书架)。
**范围**：新增 `RootTabView`、`ListenTabView`(听书书架);改 `ChildVideoApp`(路由壳)。

- **Story F1 — 底部 Tab 壳**
  - 作为孩子,我想底部能切「首页 / 听书 / 我的」(分类由 001 接入凑成四 Tab),以便看和听分开。
  - **AC**：[ ] iOS 底部 Tab、macOS 侧栏;[ ] 切 Tab 不打断网络/播放;[ ] 全屏态(播放/休息/激活)能盖在 Tab 之上;[ ] 与 001 的 RootTabView 结构兼容(预留「分类」位)。
- **Story F2 — 听书 Tab：独立书架**
  - 作为孩子,我想在「听书」Tab 看到所有书、能按分类筛选、能继续收听。
  - **AC**：[ ] 「继续收听」行(有进度的书);[ ] 分类 chips(由 audiobooks 的 category 动态生成,含「全部」);[ ] 书籍封面网格;[ ] 点书进 `AudiobookDetailView`(章节列表,003 已实现,复用)。

### Epic G：全局音频播放器 + 迷你条 + 全屏播放器
**目标**：音频播放全局化,可跨 Tab 续播、迷你条常驻、全屏可展开。
**范围**：新增 `AudioController`(`AppModel` 持有)、`MiniPlayerBar`、重构 `AudioPlayerView` 为全局视图。

- **Story G1 — 全局 AudioController**
  - 作为开发者,我想播放状态由 `AppModel` 持有(而非页面 `@StateObject`),以便切页/切 Tab 不中断。
  - **AC**：[ ] `AudioController` 封装 PlayerEngine + 当前书/章/进度/播放态;[ ] `play(book, chapter)` / 暂停 / 上下章 / seek;[ ] 心跳上报复用 003 的 `reportAudioProgress`(时段/时长拦截生效);[ ] 章末自动连播下一章。
- **Story G2 — 迷你播放条（跨 Tab 常驻）**
  - 作为孩子,我想在哪个 Tab 都能看到正在听的书并控制,以便边玩边听。
  - **AC**：[ ] 听书在播时,底部(Tab 之上)显示迷你条(封面+书名章节+播放/暂停+进度);[ ] 点迷你条展开全屏播放器;[ ] 不在播时不显示。
- **Story G3 — 全屏听书播放器（全局化重构）**
  - 作为孩子,我想点开有完整的播放界面(封面/章节/进度/上下章)。
  - **AC**：[ ] 由 003 页面级重构为读 `AudioController` 的视图;[ ] 下滑/返回**不**停止播放(回到迷你条);[ ] 章节切换、±15s、scrub、收藏。

### Epic H：睡眠定时 + 后台续播
**目标**：睡前听书刚需 + 熄屏继续播。
**范围**：`AudioController`(定时器)、播放器/迷你条入口。

- **Story H1 — 睡眠定时**
  - 作为家长/孩子,我想设「N 分钟后自动停」,以便睡前听。
  - **AC**：[ ] 全屏播放器可选 15/30/60 分钟或「本章结束」;[ ] 到点淡出暂停;[ ] 迷你条/播放器显示剩余。
- **Story H2 — 后台 / 熄屏续播**
  - 作为孩子,我想锁屏后还能继续听。
  - **AC**：[ ] 切后台/锁屏音频继续(`UIBackgroundModes: audio` + 全局播放器);[ ] 锁屏控制(NowPlaying)显示书/章并可控(已具备,确保全局生效)。

## 5. 数据 / 接口影响
- **无新后端**：复用 003 的 manifest `audiobooks` 与 Worker 路由。
- **客户端**：新增 `AudioController`(全局)、`RootTabView`、`ListenTabView`、`MiniPlayerBar`;`AudioPlayerView`/`AppModel` 重构;听书进度仍复用 `watch_progress`(键 `"<bookId>#<chIdx>"`)。

## 6. 里程碑 / 优先级
- **P0**：Epic F（Tab 壳 + 听书 Tab）、Epic G（全局播放器 + 迷你条 + 全屏重构）—— 打通「分 Tab + 边听边逛」。
- **P1**：Epic H（睡眠定时 + 后台续播打磨）。

## 7. 测试与验收总览
- 两端构建通过（macOS + iOS）。
- 模拟器走查:首页(纯视频)↔ 听书 Tab(挑书)↔ 全屏播放 → 切到首页**音频不停**、迷你条在 → 睡眠定时到点停 → 锁屏续播。
- 家长管控:听书与视频统一计入时长/时段,超限触发休息页。
- 回归:视频播放、激活、家长设置不受影响。
